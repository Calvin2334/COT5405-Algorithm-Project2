## 1. Overview of the greedy algorithm

For the COT5405 Analysis of Algorithms project, we model traffic signal scheduling as a **maximum-cardinality interval scheduling problem**.

The objective is to select the largest possible number of nonoverlapping, preapproved green-light windows for a particular traffic movement.

Each window contains three values:

```cpp
struct GreenWindow {
    int id;
    int start;
    int finish;
};
```

Here, `id` identifies the window, `start` represents its starting time, and `finish` represents its ending time.

The algorithm uses the **earliest-finish-time greedy strategy**: always choose the compatible window that finishes earliest.

This strategy is optimal for the simplified interval scheduling problem because selecting an earlier-finishing window leaves at least as much time available for subsequent windows.

## 2. Step-by-step algorithm explanation

The algorithm works in five steps:

1. **Store candidate windows:** Place all green-light windows into a C++ `vector`.
2. **Sort by finishing time:** Use `std::sort` to arrange the windows from earliest finishing time to latest.
3. **Initialize the schedule:** Create an empty vector named `selected` and initialize `lastFinish` to a value before all valid start times.
4. **Check compatibility:** Examine each sorted window. If its starting time is greater than or equal to `lastFinish`, select it and update `lastFinish`.
5. **Return the result:** Output the selected windows and their total count.

The central compatibility condition is:

\[
s_i \geq f_{\text{last}}
\]

where \(s_i\) is the candidate window's starting time and \(f_{\text{last}}\) is the finishing time of the last selected window.

## 3. Algorithm pseudocode

<CodeBlock language="text">
GREEDY-WINDOW-SCHEDULING(W)

Input:
    W = collection of green-light windows

Output:
    S = maximum-cardinality compatible set

1. Sort W by ascending finishing time
2. S = empty list
3. lastFinish = -infinity

4. For each window w in W:
5.     If w.start >= lastFinish:
6.         Add w to S
7.         lastFinish = w.finish

8. Return S
</CodeBlock>

The algorithm does not require checking every possible subset of candidate windows. It makes one selection decision for each window after sorting.

## 4. Complete C++17 implementation

The following program uses the same five candidate windows from the project. It uses `struct`, `vector`, and `std::sort` as required.

<CodeBlock language="cpp" editable>
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

// Structure representing a green-light window
struct GreenWindow {
    int id;
    int start;
    int finish;
};

int main() {

    // Candidate green-light windows
    vector<GreenWindow> windows = {
        {1, 0, 10},
        {2, 2, 5},
        {3, 5, 8},
        {4, 7, 12},
        {5, 8, 14}
    };

    // Display original windows
    cout << "Available Green-Light Windows:\n";

    for (const auto& window : windows) {
        cout << "Window " << window.id
             << ": " << window.start
             << " - " << window.finish
             << " seconds\n";
    }

    // Sort windows by earliest finishing time
    sort(windows.begin(), windows.end(),
         [](const GreenWindow& a, const GreenWindow& b) {
             return a.finish < b.finish;
         });

    // Store selected compatible windows
    vector<GreenWindow> selected;

    // Valid because starting times are nonnegative
    int lastFinish = -1;

    // Greedy selection
    for (const auto& window : windows) {

        if (window.start >= lastFinish) {
            selected.push_back(window);
            lastFinish = window.finish;
        }
    }

    // Display selected windows
    cout << "\nSelected Green-Light Windows:\n";

    for (const auto& window : selected) {
        cout << "Window " << window.id
             << ": " << window.start
             << " - " << window.finish
             << " seconds\n";
    }

    cout << "Total selected: "
         << selected.size() << '\n';

    return 0;
}
</CodeBlock>

### Explanation of the important C++ operations

**Sorting:**

```cpp
sort(windows.begin(), windows.end(),
     [](const GreenWindow& a, const GreenWindow& b) {
         return a.finish < b.finish;
     });
```

The lambda comparator tells `std::sort` to order the windows by increasing finishing time.

**Greedy selection:**

```cpp
if (window.start >= lastFinish) {
    selected.push_back(window);
    lastFinish = window.finish;
}
```

The condition prevents overlapping selections. Once a window is selected, its finishing time becomes the boundary for all future decisions.

The example initializes `lastFinish` to `-1` because all example starting times are nonnegative. For arbitrary integer starting times, use `std::numeric_limits<int>::min()` instead.

## 7. Running-time analysis

Let \(n\) represent the number of candidate green-light windows.

| Operation | Time complexity |
|---|---|
| Store or copy \(n\) input windows | \(O(n)\) |
| Sort windows using `std::sort` | \(O(n\log n)\) |
| Examine all windows | \(O(n)\) |
| **Overall** | **\(O(n\log n)\)** |

The sorting step dominates the total running time:

\[
T(n)=O(n\log n)+O(n)
\]

Therefore,

\[
\boxed{T(n)=O(n\log n)}
\]

The selected-window vector requires up to \(O(n)\) additional storage. The sorting operation itself uses logarithmic auxiliary stack space for the standard C++ implementation.

## 8. Why the algorithm is optimal

The algorithm's correctness follows from its greedy-choice property.

Suppose an optimal schedule begins with window \(o_1\), and the greedy algorithm chooses window \(g\), which finishes earliest.

Because \(g\) is the earliest-finishing candidate,

\[
f(g)\leq f(o_1)
\]

Replacing \(o_1\) with \(g\) does not prevent any subsequent window in the optimal schedule from being selected, because \(g\) finishes no later.

Therefore, an optimal solution exists that includes the first greedy choice.

The same reasoning applies after each selection, establishing that the algorithm returns a maximum-cardinality compatible schedule.

This proof relies on the simplified interval scheduling assumptions rather than the full constraints of a real traffic signal system.

## 9. Application to traffic signal scheduling

In the project domain, the algorithm can act as a scheduling component that chooses among predefined, feasible green-light opportunities.

Its practical interpretation is:

- Sort available green-light opportunities by their finishing times.
- Approve the earliest-finishing available opportunity.
- Skip opportunities that conflict with an already selected window.
- Repeat until every opportunity has been considered.

This maximizes the **number of approved compatible green-light windows**, not the total green-light duration, total vehicles served, or the reduction in congestion.

## 10. Conclusion

The earliest-finish-time greedy algorithm provides an efficient and optimal solution to the maximum-cardinality interval scheduling problem.

For the five example green-light windows, the algorithm selects windows 2, 3, and 5, producing three compatible opportunities.

Its theoretical running time is \(O(n\log n)\), and its greedy choices can be justified using an exchange argument.
