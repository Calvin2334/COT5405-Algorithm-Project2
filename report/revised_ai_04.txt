## 1. Purpose of the experiment

The objective is to experimentally evaluate the running time of your C++ greedy traffic signal scheduling algorithm and compare the measurements with its theoretical complexity:

\[
\boxed{T(n)=O(n\log n)}
\]

Your algorithm performs two main operations: sorting candidate green-light windows by finishing time and selecting compatible windows in a single pass.

| Operation | Theoretical time |
|---|---|
| Sort the \(n\) candidate windows | \(O(n\log n)\) |
| Check compatibility for all windows | \(O(n)\) |
| **Overall algorithm** | **\(O(n\log n)\)** |

We'll use a reproducible C++ benchmark that measures both sorting and greedy selection.

## 2. Experiment design

The benchmark will use the following settings:

| Parameter | Value |
|---|---|
| Programming language | C++17 |
| Compiler optimization | `-O2` |
| Random seed | `42` |
| Starting times | Random integers from 0 to 1,000,000 |
| Window durations | 1–100 seconds |
| Input sizes | 1,000 to 200,000 |
| Repetitions | 10 per input size |
| Timing method | `std::chrono::steady_clock` |
| Reported statistic | Median time in milliseconds |
| Output file | `Greedy/results.csv` |

The input sizes are:

\[
n\in\{1000,5000,10000,25000,50000,100000,200000\}
\]

For each input size, we'll generate one dataset and run the same algorithm 10 times using fresh copies of that dataset.

This allows us to measure execution time without including random-input generation in the timed portion.

The CSV will store three columns:

```text
InputSize,MedianTimeMs,NLogN
```

`NLogN` represents \(n\log_2(n)\), which we'll later use for comparison against measured running times.

## 3. Complete C++17 benchmark — `Greedy/experiment.cpp`

This version follows your existing project's approach. It also includes a small `benchmarkSink` variable so the compiler cannot discard the greedy selection results as unused work.

<CodeBlock language="cpp" editable>
#include <iostream>
#include <vector>
#include <algorithm>
#include <chrono>
#include <random>
#include <fstream>
#include <cmath>

using namespace std;

struct GreenWindow {
    int id;
    int start;
    int finish;
};

// Makes the benchmark result observable.
volatile size_t benchmarkSink = 0;

int main() {

    // Input sizes for the experiment
    vector<int> sizes = {
        1000, 5000, 10000, 25000,
        50000, 100000, 200000
    };

    // Fixed seed for reproducibility
    mt19937 rng(42);

    // Random starting times and durations
    uniform_int_distribution<int> startDist(0, 1000000);
    uniform_int_distribution<int> durationDist(1, 100);

    // Greedy/ must already exist
    ofstream csv("Greedy/results.csv");

    if (!csv.is_open()) {
        cerr << "Error: Cannot open Greedy/results.csv\n";
        return 1;
    }

    csv << "InputSize,MedianTimeMs,NLogN\n";

    for (int n : sizes) {

        vector<GreenWindow> windows;
        windows.reserve(n);

        // Generate input before starting the timer
        for (int i = 0; i < n; i++) {

            int start = startDist(rng);
            int finish = start + durationDist(rng);

            windows.push_back({
                i + 1, start, finish
            });
        }

        vector<double> times;
        times.reserve(10);

        // Run 10 repetitions
        for (int repeat = 0; repeat < 10; repeat++) {

            // Copying is NOT part of the timing
            vector<GreenWindow> testWindows = windows;

            auto startTime =
                chrono::steady_clock::now();

            // Step 1: Sort by earliest finishing time
            sort(
                testWindows.begin(),
                testWindows.end(),
                [](const GreenWindow& a,
                   const GreenWindow& b) {
                    return a.finish < b.finish;
                }
            );

            // Step 2: Greedy selection
            vector<GreenWindow> selected;

            int lastFinish = -1;

            for (const auto& window : testWindows) {

                if (window.start >= lastFinish) {

                    selected.push_back(window);
                    lastFinish = window.finish;
                }
            }

            auto endTime =
                chrono::steady_clock::now();

            // Keep the selection result observable
            benchmarkSink = selected.size();

            // Convert elapsed time to milliseconds
            chrono::duration<double, milli> elapsed =
                endTime - startTime;

            times.push_back(elapsed.count());
        }

        // Find the median of the 10 measurements
        sort(times.begin(), times.end());

        double medianTime =
            (times[4] + times[5]) / 2.0;

        // Theoretical n log2(n) comparison
        double theoretical = n * log2(n);

        // Save results to CSV
        csv << n << ","
            << medianTime << ","
            << theoretical << "\n";

        cout << "Input size: " << n
             << " | Median runtime: "
             << medianTime << " ms\n";
    }

    csv.close();

    cout << "\nResults saved to Greedy/results.csv\n";

    return 0;
}
</CodeBlock>

### How the benchmark works

**Input generation:** The program uses the Mersenne Twister random number generator (`mt19937`) with a fixed seed of `42`. Each candidate window receives a random starting time and duration.

**Sorting:** `std::sort` arranges the candidate windows in ascending order of their finishing times.

**Greedy selection:** The algorithm selects a window if its starting time is at least the finishing time of the previously selected window.

**Timing:** `std::chrono::steady_clock` measures the time for sorting and selection. Creating random input and copying the input vector are excluded.

**Median:** For each input size, 10 execution-time measurements are sorted, and the average of the middle two values is reported.

The selected-window vector is included in the timed work, so the measurement captures the implementation's allocation and insertion overhead as well as sorting and selection.

## 7. Limitations of the experiment

Several factors can influence the measurements:

- **Hardware:** Processor speed, cache behavior, and memory performance affect execution time.
- **Operating system:** Other applications and background processes may influence timings.
- **Compiler optimization:** `-O2` can significantly change runtime compared with an unoptimized build.
- **Input distribution:** Randomly generated intervals may not represent actual traffic signal schedules.
- **Small measurements:** Short executions can be influenced by clock resolution and system noise.
- **Repeated data:** Each input size uses the same dataset for all 10 repetitions, so cache effects and input characteristics may influence results.

For stronger experimental evidence, the benchmark could also test several independently generated datasets per input size.

The benchmark provides a reproducible method for evaluating the earliest-finish-time greedy scheduling algorithm.

It measures the combined cost of sorting and interval selection, uses seven input sizes, repeats each test 10 times, and records median execution times in a CSV file.

The previously recorded experimental results show increasing execution times consistent with the theoretical \(O(n\log n)\) running-time analysis.

The algorithm remains optimal for maximizing the number of mutually compatible, preapproved green-light windows, rather than directly minimizing traffic congestion.
