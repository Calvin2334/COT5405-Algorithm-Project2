## 1. Real-world problem: Traffic signal scheduling

Traffic congestion is a common challenge in urban transportation systems. When traffic signals are poorly coordinated, vehicles may encounter unnecessary stops, increasing travel delays and contributing to congestion.

One challenge is scheduling green-light opportunities so that they do not conflict with one another.

For this project, we consider a simplified traffic signal scheduling system in which a traffic controller receives a collection of **preapproved candidate green-light time windows** for a particular traffic movement.

Each candidate window represents an interval during which that movement could receive a green signal.

The controller must select as many compatible windows as possible while ensuring that no two selected windows overlap.

**Optimization objective:** Maximize the number of nonoverlapping green-light windows.

This is a variation of the classical **interval scheduling problem**, which can be solved optimally using a greedy algorithm.

## 2. Mathematical abstraction

### Define the candidate windows

Let

\[
W=\{w_1,w_2,\ldots,w_n\}
\]

represent the set of candidate green-light windows, where \(n\) is the total number of windows.

Each candidate window is represented as

\[
w_i=(s_i,f_i)
\]

where:

- \(s_i\): starting time of window \(i\).
- \(f_i\): finishing time of window \(i\).
- \(s_i < f_i\): every window has positive duration.

For example, a window represented by \(w_1=(0,10)\) begins at 0 seconds and finishes at 10 seconds.

### Compatibility constraint

Two selected windows must not overlap.

Suppose window \(w_i\) is scheduled before window \(w_j\). They are compatible when

\[
\boxed{f_i\leq s_j}
\]

This means the second window can begin immediately when the first window finishes.

### Objective function

Let \(S\subseteq W\) denote the set of selected windows.

The goal is to find

\[
\boxed{\max_{S\subseteq W}|S|}
\]

subject to all selected windows being mutually compatible.

Equivalently, the optimization problem can use binary variables \(x_i\), where \(x_i=1\) indicates that window \(i\) is selected and \(x_i=0\) means it is not.

The objective becomes

\[
\max \sum_{i=1}^{n}x_i
\]

subject to

\[
x_i+x_j\leq 1
\]

for every pair of overlapping candidate windows \(i\) and \(j\).

The greedy algorithm sorts the candidate windows by their finishing times.

The sorted order is:

\[
w_2,\ w_3,\ w_1,\ w_4,\ w_5
\]

It then selects:

- **Window 2:** \((2,5)\)
- **Window 3:** \((5,8)\)
- **Window 5:** \((8,14)\)

Each selected window starts at or after the previous selected window finishes.

Therefore,

\[
S=\{w_2,w_3,w_5\}
\]

and

\[
\boxed{|S|=3}
\]

This selection is optimal because no compatible schedule can contain more than three windows for this example.

## 4. Why a greedy algorithm works

The greedy strategy is to **select the available compatible window that finishes earliest**.

Choosing the earliest-finishing window leaves as much room as possible for future windows.

For example, selecting Window 2, which finishes at 5 seconds, allows the algorithm to select Window 3 immediately afterward.

Selecting Window 1 instead would occupy the time from 0 to 10 seconds, eliminating several other candidate opportunities.

This illustrates the greedy-choice property: choosing an earliest-finishing compatible window preserves the possibility of constructing an optimal solution.

The algorithm has two main operations:

| Operation | Time complexity |
|---|---|
| Sort candidate windows by finishing time | \(O(n\log n)\) |
| Examine each window once | \(O(n)\) |
| **Total** | **\(O(n\log n)\)** |

The correctness of this algorithm can be established formally using an exchange argument.

## 5. Assumptions of the model

The interval scheduling abstraction relies on the following assumptions:

1. **Preapproved windows:** Each candidate green-light window has already been determined to be feasible and safe.
2. **Single traffic movement or shared scheduling resource:** The model applies to a collection of windows that must not overlap.
3. **Equal importance:** Every candidate window contributes exactly one unit to the objective, regardless of its duration.
4. **Fixed intervals:** Starting and finishing times are known and cannot be changed by the greedy algorithm.
5. **No additional constraints:** The simplified optimization ignores traffic volume, pedestrian timing, minimum green durations, vehicle queues, and changing road conditions.

These assumptions make it possible to use the standard interval scheduling algorithm while acknowledging that actual traffic signal control is more complex.

## 6. Limitations: Compatible windows versus traffic congestion

A critical distinction is that **maximizing the number of compatible green-light windows does not mean minimizing traffic congestion.**

| What this algorithm optimizes | What it does not optimize |
|---|---|
| Number of selected windows | Actual vehicle throughput |
| Nonoverlapping scheduling | Average vehicle waiting time |
| Compatibility of fixed intervals | Queue lengths at intersections |
| Efficient selection of candidate opportunities | Overall green-light duration |
| Theoretical scheduling optimality | Traffic conditions across a road network |

For example, the algorithm could select three short green-light windows instead of one long window. Although that increases the number of selected opportunities, the longer window might serve more vehicles.

A realistic traffic signal optimization system would need additional information such as vehicle arrival rates, intersection capacities, queue lengths, pedestrian requirements, and minimum signal timing constraints.

Therefore, this project should be described as **optimizing the scheduling of preapproved green-light opportunities**, rather than claiming to solve traffic congestion.

## 7. Conclusion

The traffic signal scheduling problem can be modeled as a maximum-cardinality interval scheduling problem when candidate green-light windows have fixed starting and finishing times, equal importance, and must not overlap.

The earliest-finish-time greedy algorithm produces an optimal selection of mutually compatible windows in \(O(n\log n)\) time.

This model demonstrates how a classical greedy algorithm can be applied to a simplified transportation scheduling problem. Its optimality applies to the mathematical abstraction and does not guarantee improved traffic congestion or vehicle throughput in real-world intersections.
